# 手机前台连接恢复验证（#1552）

用户截图：打开手机 App 后，会话历史显示 `connection closed: Error Domain=NSPOSIXErrorDomain Code=53 "Software caused connection abort"`。

## 定位

- `HostStore.setAppVisible` 原先调用 `reconnectNow`，但本地状态仍为 `.connected` 时直接返回，没有对已失效的旧连接做前台校验。
- `DaemonConnection` 保活超时后取消等待入站消息的任务，但原 continuation 不响应取消，导致 task group 不能退出，后续失败计数和关闭连接无法执行。
- 历史补拉及订阅的失败处理未隔离已取消或已被替换的连接；断线异常直接写入历史错误。补拉锁原先仅按 agent ID 标记，旧连接未结束时会阻止新连接补拉。

截图只能说明连接被中止，不能判定当时是系统挂起、网络切换还是服务端断开。上述客户端恢复缺陷可独立复现。

## 修改

- 回到前台且本地仍标记已连接时，执行现有协议的 session ping，3 秒无响应则关闭旧连接，由原有循环重连、重新订阅并补拉历史。
- 保活等待支持取消；同时记录入站版本，防止 pong 早于 waiter 注册而被漏掉。
- 补拉按连接归属隔离，新连接可以开始恢复，旧请求不能写入错误或清理新连接的加载状态。
- 重连同步开始时清理旧错误；连接关闭和取消不再作为历史业务失败显示。真正的服务端历史读取错误仍保留重试入口。
