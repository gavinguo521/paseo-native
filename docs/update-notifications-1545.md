# Mac 更新提醒（#1545）

- 启动和回到前台调用同一检查逻辑；自动请求最少间隔 30 分钟，后台运行时按上次尝试时间安排下一次检查。
- 失败也记录尝试时间，避免频繁切前台重复请求。手动检查不受自动开关、跳过版本或时间间隔限制。
- 同一版本自动提示一次，记录跨重启保存。「以后再说」在 24 小时后允许再次自动提示；「跳过」持续抑制该版本。新版本独立判断。
- 最新发布信息缓存在本机；设置中的下载入口在重启、限频或检查失败时仍可使用，当前版本已经追上时不再显示旧下载提示。
- 只检查 GitHub Releases 并打开下载链接，不自动安装，不引入 APNs，也不在 App 完全退出后检查。

## 验证证据

`UpdateCheckerTests` 的 5 项测试通过，使用独立 UserDefaults、可控时钟和测试闭包，不等待真实半小时或一天：

1. 前台/重复触发的限频、跨重启去重与缓存恢复。
2. 延后 24 小时、跳过以及手动检查绕过自动限制。
3. 失败限频、手动错误反馈、下载入口保留。
4. 跳过旧版不影响新版提醒，版本号比较保持不变。
5. 多入口并发只发送一个请求，检查过程中关闭自动更新不会弹出自动提示。

独立 Mac 测试应用使用已有 DEBUG 版本覆盖环境变量，将本机版本设为 0.0.0，读取真实 GitHub 最新发布信息；观察到原生更新弹窗、三个操作按钮和 24 小时说明。实际点击「以后再说」后，测试应用偏好中的 snoozedVersion 为 1.0.13，snoozedUntil 为翌日相同时间，设置页仍显示查看说明与下载按钮。测试使用独立应用标识和连接钥匙串条目，没有连接真实会话，也没有下载或发布版本。

复测：使用项目的 Mac XCTest scheme，限定 `-only-testing:PaseoTests/UpdateCheckerTests`。调试构建默认不自动联网检查；真实自动检查只在正式构建或显式设置 `PASEO_UPDATE_VERSION` 的测试构建启用。

## 发布后的生效范围

现有用户需要先更新到包含本改动的版本，后续才按新频率检查。旧客户端仍使用旧频率。本地提交、推送代码或只增加 build 号都不会触发远端更新提示；仍需提高 x.y.z 版本号，签名、公证并发布 GitHub 正式 Release。
