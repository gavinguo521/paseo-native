# 1.0.25 耗电相关修复验证（#1593）

用户截图显示前台活动 3 小时 3 分钟、后台 9 分钟，并提示通知频繁。该截图没有给出单位时间功耗，不能单独证明通知或后台异常耗电。

确认的开销：灵动岛按工作区汇总时，每个工作区都会重新扫描主机全部会话、建立子会话索引。修复为每台主机只建一次，沿用相同过滤和状态优先级。另在 App 不活跃时跳过本地摘要和逐会话定时刷新；保留推送令牌登记、通知和会话后台操作。运行圆圈在低电量模式、减少动态效果及不活跃时停转，移出窗口后移除动画。

## 可重复测量

使用 MobileTests/EnergyWorkTests.swift，在同一 iPhone 17e / iOS 26.5 模拟器、同一 Debug 构建配置执行。样本来自 SidebarTestFixture，无真实业务写入。

| 样本 | 修复前，10 次摘要 | 修复后，10 次摘要 |
| --- | --- | --- |
| 30 项目 / 480 会话 | 0.2002 秒 | 0.0110 秒 |
| 100 项目 / 1600 会话 | 2.0645 秒 | 0.0357 秒 |

大样本计算耗时下降约 98%。这只是摘要计算耗时，不代表整机耗电下降 98%。

同组测试覆盖多层子会话待批准、工作区计数、已归档排除、复用索引与原计算结果一致，以及动画停转、恢复、离开窗口移除。与 MobileFeatureTests 合计 4 项通过。生命周期改动已独立静态评审通过。

仍需真机在相同亮度、网络、使用时长和会话负载下对比电池表现；本次未修改通知策略，也没有把正常批准/完成通知关闭来制造省电效果。
