# 会话切换计时与优化

2026-11-06，在实际使用的 macOS Paseo Native DEV（Debug）上验证。

## 计时方法

`PASEO_SWITCH_TRACE=1` 开启单调时钟计时：侧边栏动作入口、导航状态更新、会话 onAppear、内容滚动几何回调、布局后主队列让出、订阅开始/确认/结束、历史请求开始/返回/发布。日志只包含会话 ID 前缀、行数和耗时。`layoutYield` 表示布局回调后主队列重新执行，不等同于屏幕像素呈现时间。

开发复测入口用 `PASEO_SWITCH_BENCH=1 PASEO_SWITCH_TARGETS=<id前缀1>,<id前缀2>,<id前缀3>` 调用与侧栏相同的 `openRow`，每次间隔 5 秒，共三轮；设置 `PASEO_SWITCH_HISTORY_PAGES=8` 会在第一轮后加载较早的八页。仅切换和读取历史，不提交消息。测试期间不读取 AX 树，避免自动化无障碍遍历污染结果。基线和优化版均为 Debug。

## 确认的问题

- 导航状态更新通常只需约 2–5 ms；已缓存长会话仍要同步创建、测量所有已加载消息。221 行会话的两次基线布局后让出分别为 1049.14 / 1033.91 ms；订阅请求直到这一阶段完成才开始。
- 新订阅已确认后还等待旧订阅释放，额外增加一次网络往返。冷打开还受订阅和历史请求影响。
- 初始底部定位期间可能短暂报告顶部几何位置，原逻辑会将其当成向上阅读而自动加载更多历史，进一步扩大渲染量。

## 改动

首屏只创建最近 16 个显示项，使用稳定起始 ID 固定阅读窗口；滚到顶部或点击“加载更早”分段展开缓存，再请求远端历史。底层历史数据不截断，搜索仍使用独立历史窗口。继续使用普通 VStack 保持确定的滚动高度，避免之前 LazyVStack 的底部偏移问题。

阅读状态在视图创建时注入，恢复窗口起点与偏移；初始定位不触发自动历史加载。新订阅确认后异步清理旧订阅，历史请求不再等待其往返。

## 本地证据

原始日志保存在 `build.noindex/switch-timing/`，不纳入 Git。`baseline-long.log` 的第 1–9 次为固定复测，后续用户操作不纳入统计。真实会话仍可能收到新消息，最终对照优先使用已结束、行数不变的会话。

## 结果与边界

固定 221 行、已结束会话，两次同组热切换：

| 阶段 | 优化前 | 最终复测 |
| --- | --- | --- |
| 内容布局回调 | 470 / 436 ms | 111 / 138 ms |
| 布局后主队列让出 | 1049 / 1034 ms | 401 / 480 ms |

平均布局后让出从 1042 ms 降至 440 ms，约降低 58%。最终三会话六次热切换为约 0.30–0.48 秒；历史行数为 221 / 340–343 / 122–125，首屏均只创建 16 个显示项。普通冷打开仍包含网络等待。

第一轮优化复测曾出现一次 1697 ms 的布局后让出；第二轮没有重现，不能声称已经消除所有长尾。第二轮另有一次订阅确认等待约 2832 ms，但缓存的内容布局在 138 ms 已报告、主队列在 480 ms 已让出，历史同步在后台继续。该网络延迟仍会影响无缓存的冷打开。诊断用慢回调采样监视器在第二轮没有触发采样；不将 AX 工具调用耗时当作应用切换耗时。

验证：PaseoKit 64 项测试、应用时间线与侧栏 11 项测试通过；最终 Debug 构建和签名校验通过。已安装 DEV 的动态库 SHA256 与独立构建产物一致。原生界面实测确认向上展开能显示更早消息、切走再回来保留阅读段落、返回最新后滚动条到达 1，无空白页。尚未做像素级帧呈现计时，也未覆盖移动端真机。

最后关闭测试环境变量，以正常模式启动 DEV。
