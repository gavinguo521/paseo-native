# 聊天图片与手机输入

## 使用

- Mac 的「+ → 添加附件…」统一选择图片、视频和普通文件，支持多选；拖入输入框、⌘V 和右键粘贴使用同一导入逻辑，不再单列「选择图片」「选择视频」或「粘贴图片」。图片显示缩略图，视频准备采样画面，其他文件上传为附件；拖入文件不会把路径插进草稿正文。
- iPhone / iPad 使用「照片与视频…」从相册混选媒体，或「选择文件…」从系统文件中导入。文件入口选中的图片也显示为图片附件。
- Mac、iPhone、iPad 的输入框图片可点开预览，复用会话中的图片灯箱；右上角删除按钮可独立移除任意一张，关闭预览不会发送消息。
- iPhone / iPad 的「+」菜单最后一项为「相机拍照」。首次使用按系统提示允许相机；拒绝后可从提示页打开设置。拍照确认后加入当前草稿，取消保持原稿，不自动保存到相册或发送消息。
- 相机照片按正确方向转为 JPEG，最长边不超过 2048 像素，复用现有附件预览和发送流程。
- 手机点击会话空白处可收起输入法；滑动时间线时支持交互式收起，草稿保留。链接、图片预览和提问表单继续使用原有交互。
- 用户图片保留原有消息位置，竖屏图片在自己的缩略图区域内居中、按原比例显示；不会将整条消息移到会话中央。
- 会话里的图片（智能体回复、工具截图、自己发的图）可以导出：右键 / 长按选「存储图片…」或「拷贝图片」，放大后标题栏有存储按钮（Mac 上是 ⌘S）；也可以直接把缩略图或大图拖到桌面、Finder 或其他 App。导出的是原图，不是缩略图。Mac 第一次存储默认放到桌面，之后记住上次的位置；手机和 iPad 弹分享菜单，可以存到相册或「文件」。
- 历史窗口到达最新消息后移除「加载更多」并返回实时更新；只有确有更早或更新内容时才显示相应翻页入口。

## 跨端同步与边界

### 录屏辅助分析

- Mac 的「添加附件…」、文件拖入和粘贴支持视频；iPhone / iPad 可从「照片与视频…」或「选择文件…」添加 MP4 / MOV 等系统可解码的视频。相机拍照入口仍在菜单最后一项。
- 添加后在本机准备画面，草稿卡片显示进度、文件名、时长和画面数。点击可播放原视频，并查看即将发给 AI 的采样画面；支持取消、删除和失败后重试。处理失败会显示具体错误，不再只有红色图标。
- 发送的是带实际时间戳的图片和时间顺序说明，复用现有图片输入与跨端图片同步。原始视频不上传，音轨不转写、不发送。AI 所选模型仍需支持图片输入，不要求另配视频服务或密钥。
- 画面覆盖片头至片尾，短视频约每 0.5 秒一帧，最多 48 帧；更长的视频按全片时长拉大采样间隔。采样可能遗漏一闪而过的错误、具体触点或快速动画，建议裁剪到问题发生前后再发送。预览页会明确提醒这一边界。
- 单个视频最多 3 分钟、500 MB；文件以 URL 解码，不把整段视频加载到内存或塞入消息。JPEG 画面带独立时间条，竖屏方向保持正确；本次全部图片字节超过 20 MiB 时阻止发送并保留草稿。普通文件仍受原有 50 MB 上传限制。
- 发送前的视频副本由草稿持有；删除、取消或发送成功释放草稿后清理。排队和发送失败会保留副本和提取结果，重试不会重复附加画面。历史中可预览各帧，暂不提供跨端播放原视频。

`VideoAttachmentTests` 覆盖采样边界、HEVC 解码和旋转、时间戳、消息附件组装、队列/重试/删除、字节预算、无效视频及取消。可通过测试进程环境变量 `PASEO_TEST_VIDEO` 指定额外本地录屏；`PASEO_TEST_VIDEO_OUTPUT` 可选导出取证画面和发送参数，均不写入仓库。真实设备上仍需覆盖相册下载、预览播放、删除和发送到另一客户端的完整交互。

`ComposerAttachmentImportTests` 覆盖原生输入框的混合文件拖拽、粘贴导入、草稿/光标保留和普通路径文本。文件上传等待 JSON 请求发送完成后才依次发送 FileBegin、FileChunk、FileEnd，不依赖固定延时；`FileUploadTests` 覆盖延迟请求、并发上传、取消、超时和发送失败。

daemon 的规范用户消息不回传图片字段。发送端先用已有文件接口上传图片，并按消息 ID 发布主机侧索引，成功后才发送原有文字和图片参数。接收端按同一消息 ID 恢复图片。数据格式、缓存和能力要求见[消息协议](protocol/02-messages.md#user_message)。

图片和索引保存在会话所属的主机上，读取仍经过已配对的连接，不增加服务器或插件。新图片同步要求发送端和接收端都包含该实现；旧版本仅保留在发送端内存中的图片不会自动补齐。索引或上传失败会阻止本次发送并保留草稿供重试。

索引目录是 `~/.paseo/native-message-images/v1`，文件名是消息 ID 的 SHA-256 加 `.json`。排查时先确认两端连接同一主机，再检查索引与其中引用的上传文件是否存在。删除这些文件会影响历史图片恢复；当前没有自动清理策略。

## 回归验证

自动检查：

```sh
swift test --package-path PaseoKit
xcodegen generate
xcodebuild -project Paseo.xcodeproj -scheme Paseo -configuration Debug \
  -destination 'platform=macOS' -derivedDataPath build/chat-image-tests \
  -skipPackagePluginValidation CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual \
  PASEO_BUNDLE_ID=com.example.paseo.image-tests \
  -only-testing:PaseoTests/UserMessageImageTests \
  -only-testing:PaseoTests/TimelinePerformanceTests test
```

`MessageImageTests` 覆盖跨客户端恢复、顺序、主机隔离、索引校验、并发合并、读取上限与错误重试。`UserMessageImageTests` 挂载实际时间线行，验证没有本地预览时仍会加载远端图片。`TimelinePerformanceTests` 覆盖历史窗口、实时尾部合并及图片方向。

手动检查：

1. 输入框添加三张图，逐张预览并关闭，先删中间一张再删第一张，确认剩余图片正确。
2. 手机拍一张竖屏照片，确认后检查草稿预览；再取消一次拍照，确认草稿不变。验证首次权限、拒绝权限后返回和设置授权路径。
3. 输入一段中文，点击会话空白处及滑动时间线，确认键盘收起、草稿保留；检查图片、链接和表单仍能操作。
4. 向测试会话发图，在另一原生客户端打开同一会话，确认图片顺序、缩略图与大图；重开会话验证恢复。分别覆盖已有会话、新会话和新工作区。
5. 从历史搜索结果向后翻页至末尾，确认「加载更多」消失，后续消息继续更新。

2026-11-06 的设备验证已确认 Mac 草稿图片预览与任意顺序删除、手机拍照及收键盘操作；Mac 也已验证手机图片恢复、缩略图内居中和历史翻页末尾行为。完整权限分支、iPad 触控及所有新建入口仍需更广的设备覆盖；自动测试不替代这些交互验证。
