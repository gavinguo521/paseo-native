# 官方 App v0.14.0 与原生客户端的功能差距清单

## 结论

我们已经有 Mac 版的骨架：会话、时间线、输入框、主机页、计划任务、命令面板都有。和官方的根本差别在信息结构上：

- **官方**：一个工作区就是一个容器，里面有多个标签（Agent、终端、改动、文件、PR、浏览器），可以分屏，右侧栏可以和聊天并排显示。
- **我们**：一个会话一页，靠顶部「聊天 | 主机」分段整页切换。

用户发现的「+」标签栏就是这个差别最直接的体现，也连带了一大批快捷键和命令面板动作。另外查到一个现成 bug：在 `App/Sources/UI/ComposerView.swift` 约 559–566 行，分叉到新 worktree 时，`createWorkspace` 没有带上原会话的上下文附件和上传的文件，新会话拿不到原对话。

标注说明：
- 【E】：官方仅 Electron 桌面版有；【W】：仅 web 版有；【N】：仅原生移动版有。
- 工作量分小、中、大。
- 已排除：在 App 里编辑文件、语音听写/语音模式。

## 一、工作区、标签页与分屏

- 多标签工作区（一个工作区里同时开多个 Agent、终端、文件、diff 标签） — **已做**：会话 / 终端 / 改动 / 文件 / 新会话五种标签，按工作区记住 — 大
- 「+」新标签菜单（Agent / 终端 / 改动 / Diff / 文件 / 浏览器 / PR） — **已做** Agent、终端（含终端配置）、改动、文件；浏览器、PR 未做 — 中
- 标签右键菜单（复制恢复命令、复制 Agent/终端 ID、重命名、关闭左侧/右侧/其他、重新加载、关闭） — **已做**（含终端重命名、复制恢复命令） — 小
- 关闭确认（关终端前确认；批量关闭时汇总要归档几个 Agent、关几个终端） — **已做** — 小
- 标签拖拽排序、拖到分屏区 — **拖拽排序已做**（分屏未做） — 大
- 分屏（向右/向下拆分、窗格焦点、移动标签、关闭窗格） — 没有 — 官方原生 iPad 上也没有，桌面和 web 才有 — 大
- 手机上的标签切换下拉 — 没有 — 中（依赖标签模型）
- 单个文件开成标签 — **已做**（从回复链接打开；文件页里点仍在右侧预览） — 中
- Setup 面板（worktree 初始化命令的进度和日志，被卡住时可手动运行） — **已做**（标签栏下方横幅 + 日志弹窗 + 重新运行） — 中
- 窗格内查找（文件、终端） — **文件内查找已做**（⌘F，逐行跳转），终端查找未做 — 小

### 0.15 同步项实测记录（2026-11-06）

在隔离的 0.15.2 daemon 上测（临时 `PASEO_HOME`、独立端口），客户端是 PaseoKit，**没有点 App 界面**。

| 项 | 怎么测 | 结果 |
|---|---|---|
| 用量开关 | `patchDaemonConfig` 关 / 开，再调 `usageReports` | 通过。关闭后 `usageQueriesEnabled` 为 false，daemon 回「Usage is off on this host.」 |
| 保留终端 | 建终端跑长命令，默认重启，再用 `killTerminals` 重启 | 通过。默认重启后 worker 换了，终端 id 和进程 PID 都在；`killTerminals` 后都没了。重连后终端输出能否接上没测 |
| 分块传输 | 配置里放 40MB 字符串，读 `get_daemon_config_request` | 直连通过。声明能力时收到 2 个 `0x31` 帧，不声明时是一整条明文帧；PaseoKit 还原出 41943040 字节且连接仍可用。只有单条消息超过 32MB 才触发 |
| 恢复会话（设置开，`kill -9` worker） | Claude 会话运行中杀 worker | 通过。恢复提示语送达，会话继续 |
| 恢复会话（设置关，`kill -9` worker） | 同上 | 通过。不恢复 |
| 恢复会话（设置开，手动重启） | Claude 会话运行中 `restart_server_request` | **不恢复，官方 bug** |

**官方 bug**（0.15.2 和当时的 main 都在）：停机时 `captureRunningAgents` 写入 `resumeOnStartup`，紧接着 `closeAllAgents` 把会话关成 `idle`，`agent-storage` 的 `applySnapshot` 看到 `idle` 就清掉标记（日志里相隔 14ms）。只验证了 Claude。客户端修不了，所以重启确认框的文案改成了实际行为。
